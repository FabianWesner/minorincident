# LOD0 diet for the heaviest Level 1 assets (load time; PO wants fast loading)
Measured by the load lane (epics-pipeline/l1v2/load-report.md): LOD0 meshes are far too heavy for an isometric game camera — e.g. bld.house-a LOD0 534k vertices (LOD1 43k), bld.cafe-corner 1.27 MB, bld.clinic-annex 1.45 MB, bld.house-b 1.44 MB, bld.mainstreet-brick 1.66 MB, bld.house-d/e ~0.95 MB, bld.garage-detached 0.79 MB, vehicles 0.6–1.3 MB.
Goal: for every asset placed in D-GROVE (read layouts/D-GROVE placements / public/assets/layouts/D-GROVE.layout.json for the asset ids), bring LOD0 to ≤ ~150k vertices and ≤ ~400 KB shipped (meshopt/quantized) WITHOUT a visible quality loss at the game camera (close camera, survivor ≈ 1/5 of a 900 px frame; also check zoomed-in ≈ 1/3.5). Technique, in this order: delete invisible/interior faces and sub-centimetre detail, merge coplanar/duplicate geometry, reduce bevel/subdivision segments in build.py, then Decimate (planar first) only where invisible. Change it IN THE REPRODUCIBLE build.py (parameter or --lod0-budget path), rebuild, re-pack with the project pack tool (npm run assets:pack -- <id>), keep node names/sockets/dimensions, regenerate static collision if the pack tool requires it. Biggest offenders first (house-a, mainstreet-brick, clinic-annex, house-b, cafe-corner, house-d/e, garage, then vehicles).
