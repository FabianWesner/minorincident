# Shared worktree setup

Run `sh tools/install-worktree-hook.sh` once in this checkout. It installs an additive Git `post-checkout` hook in the common Git directory and preserves an existing hook. Git invokes it for fresh linked worktrees, so both the scheduler's `--worktree` (`prepare_worktree` uses `git worktree add`) and Claude Agent's `.claude/worktrees` creation run `tools/worktree-setup.sh` automatically. Existing worktrees can run `sh tools/worktree-setup.sh <path>` explicitly. Reinstall the hook after updating its scripts. The installer refuses to overwrite a configured `core.hooksPath`.

The store defaults to `<main checkout>/.mi-worktree-cache`; override `MI_WORKTREE_CACHE` consistently for setup and build commands. Dependencies are keyed by `package-lock.json` and copied with APFS `cp -cR` (regular-copy fallback). Each worktree owns a writable dependency clone, including Vite/Vitest's temporary config files and relative local-package links. No manual `node_modules/vite` symlink is required. Process-owned file locks release on crashes.

Vite's optimizer cache is stored centrally and partitioned by lockfile, Vite configuration, and worktree root. Vite 6 hashes `config.root` and embeds absolute package paths, so sharing one mutable optimizer directory between roots would invalidate another lane's modules; dependency packages and immutable production outputs are shared instead. `npm run build` caches `dist` only for clean Git sources, keyed by tree, commit provenance, lockfile, CLI arguments, build variant, and hashed Vite environment inputs. Dirty trees or ignored source/public inputs build locally. Cached output is cloned into a worktree's writable `dist`, so another lane's rebuild cannot modify it. Use `MI_BUILD_CACHE=off` for a cold build. The dist store keeps the three most recently used entries (`MI_BUILD_CACHE_ENTRIES` overrides this); pruning takes each entry’s process lock and never modifies existing worktree clones.

`sh tools/worktree-setup.sh --smoke` reports setup footprint/time and the elapsed time for the first green full smoke. It releases the dependency-store lock before running tests. Browser runs need private `E2E_PORT` and `SCENE_PORT` values; port 3300 is reserved for the user's dev server. Retain measurement output under `docs/reports/lane-infra/`.

Browser/legacy and sim acquisitions append `{at,lane,kind,waitMs}` to `$TMPDIR/mi-waits.jsonl`. `node tools/qa/wait-report.mjs [file]` groups by lane/resource/hour and also accepts mac-runner's `{ts,lane,lock,waitMs}` schema. Remote/local CPU slot instrumentation remains owned by the mac-runner lane. `sh tools/browser-busy.sh` exposes the shared GPU reservation probe for that lane.

The browser daemon runs from a small versioned snapshot under the shared cache, with stable dependencies. Removing the initiating worktree therefore does not break later GPU admission or Playwright launches.

`npm run build` retains the production build contract; use `npm run build:qa` for browser automation and authoring tools. Both use the shared dist cache. Its environment key includes `NODE_ENV`, `VITE_QA_HOOKS`, `BRANCH` and all other `VITE_` inputs, so cached QA output cannot replace production output. From a clean committed checkout, `node tools/qa/build-cache-check.mjs` checks production → QA → cached production, plus independent branch and Node environment changes. It checks the resolved `__QA_HOOKS__` define, emitted hook code and public QA pages after every build; receipts go to `test-results/build-cache-check/`. It leaves production output in `dist`, so run `npm run build:qa` before browser smoke.
