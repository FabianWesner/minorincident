# readability-w6c

Continues `e42afcce1` in the readability worktree. The courier now uses a bounded surface fill and mint rim, with soft local ground shading in the shared L6-exit/L7 night preset. The rim broadens with distance without multiplying its energy. Night courier pixels carry grade protection in the existing scene alpha channel; the composite restores opaque canvas alpha. This keeps the warm world grade from clipping skin and clothing, with no extra render target or pass. The world-bar overlay samples that same alpha mask so follower bars cannot paint over the courier’s face; bar anchors, dimensions and colours remain unchanged. Held equipment and the headlamp receive the same courier treatment.

L7 now carries the L6 courier model forward. The foreground reveal retains depth testing in a compressed near-camera depth interval, so the cap, hair, face and limbs occlude each other correctly while the courier remains visible through the close following crowd. ACTION prompts and the corgi rendering are unchanged. No specs, budgets or contrast thresholds were changed; staticCollision.ts has no changes.

The clipping guard counts pixels in the existing courier ID silhouette whose **any display channel / 255 >= 0.97**, and requires a share **<= 3%**. It runs for L6 and both L7 battle spots at high/low, zoom 0.5/1/1.5 and WebGL/WebGPU. The existing T-E29-14 silhouette, sixteen ring samples, >200 pixel guard and >=3 contrast assertion remain. Companion masks are read synchronously from the just-rendered canvas so a following beauty frame cannot replace the mask before it is sampled; their depth testing is explicitly restored.

## Performance investigation

The first final native batch passed E18 desktop and L6 high, but failed L6 low's 80 ms maximum (83.7 ms), L7 high's 16.7 ms p95 (16.8 ms), and L7 low's frame/sim p95 (38.4/7.9 ms against 33.3/6). Its complete measurements and captures are retained in `perf/first-final/`. L6 low's p50/p95 were 11.8/19.5 ms. These failures were not rounded, removed or relabelled as passes. The preceding w6b report recorded L7 high 15.2 ms and low 34.6/7.5 ms, so the first batch did not establish performance neutrality.

A separate diagnostic CPU profile identified the health-bar solid-geometry query as the dominant render update cost: **2,913 ms high / 1,776 ms low** of a 7,000 ms sampled window, spent in full triangle raycasts. See `perf/profile/summary.json` and the compressed original profiles. The diagnostic sampling run is not final timing evidence. The retained `L7_CPU_PROFILE=1` option profiles the existing fixture without changing its populations, duration or assertions.

`InstancedGroup.intersectsRay` now reuses an indirect triangle BVH per immutable prototype and queries each live instance transform with the original material and ray limits. It returns the same triangle-hit predicate; no geometry, placements, visibility counts or silhouettes are simplified. It does not patch global `Mesh.raycast`. The dependency is pinned to **three-mesh-bvh 0.9.16**, [MIT licensed](https://github.com/gkjohnson/three-mesh-bvh/blob/master/LICENSE); the complete notice is retained in `docs/licenses/three-mesh-bvh-0.9.16.txt` and generated in-game credits/`THIRD_PARTY_NOTICES.md` are updated. The [indirect API](https://github.com/gkjohnson/three-mesh-bvh/blob/master/API.md) avoids changing shared index buffers.

The initial interrupted timing reservation lasted less than a minute and its intermediate desktop result remains in `perf/intermediate/`. Every later native batch was separate, after releasing slots and doing other work; `quiet-run` enforces the 20-minute held-batch bound and shared cooldown. All timing is headless native Metal WebGL2, one worker. Both backends also receive the complete visual, clipping and resource-counter matrix. No performance budget or fixture scope was changed.

**Final accelerated-query native timing is unmeasured.** The final batch waited from approximately 12:41 to 13:11 CEST and exited 75 at the binding 30-minute admission limit, before starting any browser. See `perf/final-admission.log`. It was not requeued and no guard or reservation limit was bypassed. The earlier E18 desktop and L6-high passes remain evidence for the pre-acceleration build only; the failed L6-low/L7 measurements remain above. Consequently this report does **not** claim that final E18 budgets hold, despite passing final draw/triangle counters and exact ray-fidelity tests. Native E18/L6/L7 timing still needs an admitted quiet batch.
