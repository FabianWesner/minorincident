# Motion libraries and templates: evaluation and isolated prototype

Date: 2026-10-06. Branch: `lane/motion-lib`, created from `main` at `eae1267`; `git merge main` once returned already up to date. This is an evaluation, not a gameplay rollout. No running lane was merged, and no specs, reference assets, experiment tools or Bruno checkout were edited. Read `research-figures-report.md`, `bruno-tech-comparison.md` §§9–11 from the main worktree (those ignored reports were absent from this worktree), architecture, E04/E18, and test guidance.

## Decision

Adopt **three.js's existing animation stack plus better motion data and constraints**, rather than a replacement character-controller package. Keep Rapier for the survivor. Add bounded acceleration/jerk and facing changes in deterministic NPC locomotion; add phase-aware transition blending to the current GPU crowd path. Develop a small deforming skeleton for survivor/corgi/near civilians; keep bone or part textures and instancing for the bulk of infected. Evaluate Mesh2Motion as an **offline CC0 rig/animation starting point**, not a drop-in runtime dependency or final animation direction.

Main is further along than the older reports: `KeyframeAnimator` already uses `AnimationMixer`, 140 ms crossfades, additive upper-body attacks, speed-matched phase and a backpack spring; `MotionPhase` is distance-driven; `crowdMatrix` already interpolates fractional frames. Our remaining gaps are contact correctness, smoothing NPC direction/speed, transitions between crowd clips and visible rigid surfaces. The official multiple-animation example largely describes infrastructure we already have.

A real baseline defect emerged: `plantLocomotion` generated the full library stride but phase playback scaled it to short legs. At female raw-asset scale 1, sampled walk stance x positions after compensating root displacement ranged by **0.07750 m**. Separate commit `f9a77a6` scales the stance curve by the same target leg ratio; the existing support/phase tests then pass. One test expectation was corrected to include the same already-established target stride scale. No threshold was relaxed. Metrics below label the repaired baseline explicitly.

## Animation sources and motion techniques

- **Mixamo:** Adobe's FAQ permits commercial games, and auto-rigging is humanoid-only. It is a proprietary content license, not MIT/Apache/BSD/CC0. The FAQ is not an unrestricted grant to redistribute an animation library as raw assets; public game GLBs are downloadable, so retain applicable Adobe terms and distinguish integrated game content from an asset/template distribution. Prefer CC0 for this open asset pipeline. No Mixamo files were fetched, used, or committed. [Adobe FAQ](https://helpx.adobe.com/creative-cloud/faq/mixamo-faq.html), [additional terms](https://wwwimages2.adobe.com/content/dam/cc/en/legal/servicetou/Mixamo-Addl-Terms-en_US-20210623.pdf).
- **Quaternius:** Universal Animation Library is CC0. Use as pose/clip source and an independent connected-rig reference. Short chibi thighs, large head/hands and weapon offsets require fitting rest pose, support trajectories and contact lengths, not uniform scale alone. Style needs exaggeration and impact editing. [Pack and license](https://quaternius.com/packs/universalanimationlibrary.html).
- **Kenney:** Animated Characters Survivors explicitly CC0, pack 1.0 released 2019; suitable legally for public GLBs and reference comparison. Texture/skinned proportions should be retargeted, not substituted for the existing survivor identity. [Creator pack](https://kenney.nl/assets/animated-characters-survivors).
- **Blender NLA → glTF:** offline authoring/export, not a game runtime dependency. Use separate named actions/NLA tracks, bake constraints and non-exportable drivers, export skins/animation, validate joints and clip durations. Pin Blender/exporter settings; glTF does not preserve the Blender control rig or NLA editor logic. Only the authorized `experiment/tools/blender_run.py` may execute Blender. This lab did not execute Blender. [Blender export documentation](https://docs.blender.org/manual/en/4.1/addons/import_export/scene_gltf2.html).
- **Motion constraints:** bounded acceleration removes immediate velocity jumps; jerk limits smooth acceleration changes. Limit angular velocity and acceleration, unwrap angles and slerp visual quaternion between fixed snapshots. Do not smooth the hero's authoritative aim into an E04 violation. Speed-match with actual post-collision displacement, retain support phase and use start/stop hysteresis. Limits can increase arrival distance and should feed steering/braking before collision, not pull render roots through walls.
- **Foot IK:** CCDIKSolver is MIT as a three addon and works on skeleton bones independently of render backend. It needs valid joint limits and ground samples; authored flat contact plus analytical two-bone leg IK is cheaper for this humanoid use case. Run terrain corrections for survivor/corgi/near escorts, not every infected. Pin stance feet through fades and release predictably. [CCDIKSolver API](https://threejs.org/docs/pages/CCDIKSolver.html).
- **Inertialization:** preserve outgoing pose velocity and decay an offset into the new pose to improve interrupted transitions. Three has no built-in inertialization operator. It adds state and discontinuity/teleport handling; start with correctly synchronized crossfades and crowd transitions. Root, contact and combat timing remain separately constrained. The lab measures a simple crossfade, not inertialization.

## Mesh2Motion: added candidate, evaluated with actual export

The [code license](https://github.com/Mesh2Motion/mesh2motion-app/blob/79f3f61a9852ef70234a5a4a7c13ed87f7a71833/LICENSE-MIT.MD) is MIT. The separate [rig/animation license](https://github.com/Mesh2Motion/mesh2motion-app/blob/79f3f61a9852ef70234a5a4a7c13ed87f7a71833/LICENSE-CC0.MD) explicitly dedicates rigs, animations, models and blend files to CC0: the supplied rig and base-library animation data may be shipped in downloadable public web-game GLBs. Imported custom packs retain their own license; the project's model-variation registry also contains per-model exceptions, so do not treat every optional third-party model as blanket CC0. This experiment uses our model and the supplied human rig/base library only.

Maintenance: pinned checkout `79f3f61a9852ef70234a5a4a7c13ed87f7a71833`, commit 2026-09-28. Package depends on three ^0.185.0 and exposes dev/build/test scripts, **no supported rigging CLI or stable batch API**. The editor needs fitting a skeleton; it does not infer perfect joints from an arbitrary upload. Its solver and correction modules are accessible TypeScript, allowing an offline adapter. Head/arm correction planes are useful for our roughly 3.4-head figures, but automatic anatomical weights can accidentally deform backpacks, shoes, faces and sleeves. Preserve such rigid attachments and sockets explicitly.

`tools/motionlab/mesh2motion.ts` imports the pinned solver, loads our current female LOD1, fits template bone landmarks to our existing known joints, converts +X to the tool's coordinate frame and back, enables head/arm corrections, indexes geometry for adjacency smoothing, strips all positional tracks and root tracks from selected clips, exports with the standard GLTFExporter, reloads, clones with SkeletonUtils and updates a Mixer. This is a custom **pipeline adapter**, not proof that the hosted upload wizard automatically places a correct rig. Arbitrary unmapped bones/fingers still need art fitting; production should reduce the template rig and author rest-pose rotations. Removing every positional track also removes authored pelvis translation/sway: this conservative in-place adapter is not a finished retarget. A production importer should distinguish root displacement from local pose translation.

Actual export: **1,679 indexed vertices; 66 bones; 1,408 fractional weight influences; five clips (`Idle_A`, `Walk`, `Jog`, `Sprint`, `Zombie_Walk`); 562,820 bytes**. Independent rebuilds produce the same SHA-256 `4c6a9699dbe27f6010efa5b62dfc6bf81c481347d66a4d61fbfcdc302e5bed76`. We tested GLB load/clone/Mixer in Node with pinned three r186. The lab's `candidate=mesh2motion` compares its actual exported motion. Standard skin/animation format is backend-compatible; WebGPU visual checks remain manual. No tool source or hosted services are shipped at runtime.

Recommendation: a serious, permissively licensed alternative to Mixamo for offline rig/clip starting points and perhaps a repeatable custom asset-build stage. Require a connected deformation mesh, reduced rig, corrected A/T rest pose, rigid gear partition and gameplay contact/strike editing before adoption. A connected CC0 character can show the solver's full potential better than our disconnected shells; do not erase the survivor identity to get that demonstration. Quadruped templates exist (fox/horse), but the corgi still needs species/proportion-specific fitting.

## Prototype design and reproducibility

Entry: `/?motionlab&renderer=webgl&count=200`; `view=close` shows three figure types; `candidate=mesh2motion` swaps the prototype survivor. `side=current|prototype` isolates render submission costs. Defaults to 200, clamps 50–200. This route dynamically loads its code instead of creating a Game; normal gameplay and preview are unchanged. Two isolated scenes receive the same 60 Hz scripted idle → walk → run → 90° turns → stop sequence. The survivor uses the **existing actual Rapier/KinematicController** on both sides; no claim of smoother hero root motion is made. NPC baseline reproduces direct desired velocity, civilian's existing .12 rad/tick turn limit and infected immediate heading; this is a controlled policy comparison, not a full L1/Detour avoidance benchmark.

Current figure surfaces and crowd source are actual `char.survivor-female`, `npc.civilian-man-a`, `inf.jogger` LOD1 GLBs; no placeholders. The current crowd sampler is the existing `bakeInfected` and `crowdMatrix`. The skin prototype makes a named Bone hierarchy from those assets and adds up to two influences near joints, preserving rigid heads/feet/hands/gear. It uses Mixer for the hero and precomputed **deformation bone matrices** with per-instance time/transition attributes for civilians and infected. One crowd draw is retained. Infected prototype uses planted walk/run as a contact study instead of shamble/infected-run; preserve zombie hunch/acting in a production retarget, rather than shipping that stylistic change.

Prototype NPC response: velocity critical damping with acceleration ≤6 m/s² and jerk ≤48 m/s³; angular velocity ≤4.5 rad/s and angular acceleration ≤12 rad/s². These are lab hypotheses, not recommended hero balance constants. No Yuka/Detour dependency was installed just to reproduce a few arithmetic limits. No terrain IK, obstacle detour, foot contact locking during blended transitions, attack layering on new skins or dismemberment was implemented in the lab; these are explicit migration gates.

Measure: `E2E_PORT=3352 sh tools/e2e-lock.sh npx tsx tools/motionlab/measure.ts`; the harness starts and retires Vite on 3352 if that port has no server. One headless Chromium process, serial contexts, ANGLE Metal on Apple M1 Max with 32 GiB RAM, DPR1, desktop and Pixel 7 emulation (4× CDP CPU slowdown, still the desktop GPU). No windows, no extra 3300 server. Browser runs use the shared limiter only through that command; self-locking npm scripts are not double-wrapped. The orchestrator updated `tools/e2e-lock.sh` to two browser slots at the end of this study. Later checks obey that update; plain builds/typecheck/lint/unit runs stay outside the limiter. The updated tool file is an orchestrator-owned worktree change, not a motionlab commit. Motion samples are exact 1/60 s steps; third finite differences give jerk. Straight-support ankle drift is a landmark proxy (not a sole/contact force), and transition head displacement is a proxy for a pose pop (not a complete visual metric). Root translation is excluded from transition displacement; simultaneous facing rotation may still contribute to this landmark proxy. CPU update includes sim/controller, diagnostic tracing and animation upload; CPU render-submit excludes asynchronous GPU completion. Update p95 is accumulated across deterministic/GPU/realtime stepping after the first 120 samples; submit p95 discards the first 120 submissions and is mostly the realtime interval. This is an instrumented lab cost, not a production-only locomotion profile. GPU timestamps use three backend queries only if supported; null means unavailable, never zero. Mobile emulation remains this Mac GPU, not a physical phone. In single-side runs the other side is not stepped or drawn.

The final run completed 2026-10-06 at 17:06 UTC with zero browser errors; raw samples and counts are in `motion-lib-metrics.json`. The first hero probe produced zero eligible support samples because it divided total distance by one stride despite walk/run changes; that is an invalid measurement, not zero foot sliding. The corrected probe reads the evaluated r186 action phase through a debug-only mixer inspection, covers both steady walk and run, and reports null if no eligible samples. Survivor root jerk remains high because the actual Rapier controller sometimes nearly stops horizontal movement on the otherwise flat test floor. That behavior is present identically on both sides, not caused by the skinning study.

## Sim ↔ render contract

Keep gameplay position, post-collision displacement, velocity, facing and attack/contact timing in the fixed-step sim. If adopting bounded NPC response, its velocity/acceleration/angular-velocity state belongs in deterministic snapshots/replays, with stable iteration and explicit teleport resets. Test new steering against arrival distance, cornering, collisions and strikes rather than adding a render-root lag that desynchronizes hits. Render interpolates adjacent snapshots with position interpolation and quaternion slerp; it consumes movement distance and explicit clip/phase/transition state. Mixer and crowd palettes deform surfaces without moving authoritative roots. Imported root motion is removed or extracted into sim intent; never add both. Keep Rapier sweeps for the survivor and selected solid escorts, not all 200 infected. Use existing spatial/grid steering unless measured navigation failures justify a separate pathing change.
